# 자산 원장

매일 자산을 누적 관리하는 개인용 웹앱과, 카카오 알림톡의 체결 내역을 자동으로 받아오는 안드로이드 수집 앱.

```
web/       설치형 웹앱 (PWA) — 모든 화면·계산·그래프
android/   알림수집 앱 — 화면은 설정 한 장, 백그라운드에서 알림만 수집
supabase/  데이터베이스 스키마
```

## 왜 이렇게 나눠져 있나

수집 앱은 웹앱에게 **직접 말을 걸지 않습니다.** 알림을 잡으면 곧바로 폰 안의 데이터베이스에 넣고, 서버 전송은 성공할 때까지 무한 재시도하는 작업으로 넘깁니다. 웹앱은 서버에서 읽기만 합니다.

두 쪽이 공유하는 것은 데이터베이스뿐이라 **끊어질 연결 자체가 없습니다.** 앱이 꺼져 있든, 웹앱이 안 떠 있든, 비행기 모드든 알림은 디스크에 남고 네트워크가 돌아오면 자동으로 올라갑니다.

기능을 고칠 때는 `web/index.html` 한 파일만 바꾸면 됩니다. 수집 앱은 한 번 설치한 뒤 다시 손댈 일이 거의 없습니다.

---

## 설치 순서

> **저장소는 공개(Public)로 만들어도 됩니다.** 여기 올라가는 `web/index.html` 에는 금액·이름·계좌가 하나도 없습니다. 실제 자산 기록은 `supabase/seed.sql` 에만 들어 있고, 이 파일은 **저장소에 올리지 말고** 따로 빼두었다가 Supabase SQL Editor 에서 한 번만 실행하세요.

### 1단계 — Supabase 만들기 (6분)

1. [supabase.com](https://supabase.com) 가입 후 새 프로젝트 생성 (무료 플랜, 리전은 **Northeast Asia (Seoul)** 권장)
2. 왼쪽 **Authentication › Users › Add user** 에서 본인 계정을 하나 만듭니다 (메일 주소 + 비밀번호). *Auto Confirm User* 를 켜두세요.
3. 왼쪽 **SQL Editor** 에서 `supabase/schema.sql` 내용을 통째로 붙여넣고 실행
   - 이어서 따로 빼둔 `supabase/seed.sql` 도 붙여넣고 실행하면 지금까지의 기록이 들어갑니다 (한 번만)
4. 왼쪽 **Settings › API Keys** 에서 **공개 키** 를 복사해 둡니다
   - `sb_publishable_...` 로 시작하는 **Publishable key**, 또는 예전 방식의 `anon` 키(`eyJ...`) 중 화면에 보이는 쪽 아무거나 됩니다
5. 왼쪽 **Settings › Data API** 에서 `Project URL` 을 복사해 둡니다 — `https://xxxxx.supabase.co`

> 이 공개 키는 노출돼도 되는 키입니다. 실제 접근 권한은 로그인한 계정에만 열려 있고(행 수준 보안), 본인 데이터는 본인만 읽고 씁니다.

### 2단계 — 웹앱 올리기 (3분)

1. 이 저장소를 본인 GitHub 계정으로 올립니다
2. **Settings › Pages › Source** 를 `GitHub Actions` 로 바꿉니다
3. `main` 에 push 하면 자동 배포됩니다 → `https://<계정>.github.io/<저장소>/`
4. 폰 크롬으로 그 주소를 열고 **⋮ › 앱 설치** 를 누르면 아이콘이 생깁니다
5. 앱 안 **입력 › 서버 연결** 에 1단계의 주소·키·계정을 넣고 연결

### 3단계 — 수집 앱 설치 (5분)

1. GitHub 저장소의 **Actions › APK 빌드 › Run workflow** 실행 (5분쯤 걸립니다)
2. 완료되면 실행 결과 하단 **Artifacts › jasan-collector-apk** 를 폰으로 내려받아 설치
   - *출처를 알 수 없는 앱* 설치를 허용해야 합니다
   - 태그를 붙여 push 하면(`git tag v1 && git push --tags`) Releases 페이지에서 바로 받을 수 있어 더 편합니다
3. 앱을 열고 1단계의 주소·키·계정과 2단계의 웹앱 주소를 넣고 **저장하고 연결하기**
4. **① 알림 접근 허용하기** → 목록에서 *자산 원장 수집기* 를 켭니다
5. **② 배터리 최적화에서 제외하기** → 허용

#### 삼성 기기라면 한 가지 더

설정 › 배터리 › **백그라운드 사용 제한** › *사용 안 함 앱* 목록에 이 앱이 들어 있으면 빼주세요. 여기 들어가 있으면 화면이 꺼진 동안 알림을 놓칠 수 있습니다.

## 동작 확인

수집 앱 첫 화면에 이렇게 나오면 정상입니다.

```
✓ 알림 접근 허용됨
✓ 배터리 최적화 제외됨
✓ 서버 설정 완료

전송 대기: 0건
마지막 전송: 09/01 14:22
마지막 시세: 09/01 14:30
```

다음 체결 알림톡이 오면 몇 초 안에 *전송 대기* 가 1로 올랐다가 0으로 돌아갑니다. 웹앱을 열면 이미 반영돼 있습니다.

**전송 대기가 계속 쌓이면** 서버 설정이나 네트워크 문제입니다. 데이터가 사라진 게 아니라 큐에 안전하게 남아 있는 상태이니, 설정을 고치고 **지금 전송하고 시세 받기** 를 누르면 밀린 것까지 한 번에 올라갑니다.

## 시세는 어떻게 들어오나

수집 앱이 15분마다 TQQQ · SOXL · QLD · 원달러 환율 · 국내 ETF 시세를 받아 서버에 올리고, 웹앱이 그 값을 읽습니다. 앱은 브라우저와 달리 교차출처 제약이 없어 훨씬 안정적으로 붙습니다.

조회에 실패한 항목은 **전일 값을 임시로** 쓰고 화면에 `임시` 표시가 붙습니다. 다음 조회에 성공하면 자동으로 덮어씁니다. 직접 입력한 값은 그날 하루 자동 조회가 건드리지 않습니다.

## 알림톡 인식 범위

계좌번호 앞 4자리로 어느 계정인지 판별합니다.

| 앞 4자리 | 계정 | 종목 |
|---|---|---|
| `3020` | 무매 | TQQQ, SOXL |
| `3081` | VR | TQQQ |

계좌를 추가하려면 `web/index.html` 의 `const ACCTS = { '3020': 'mm', '3081': 'vr' }` 한 줄만 고치면 됩니다.

등록되지 않은 계좌나 형식이 다른 알림은 **버려지지 않고** 서버 `inbox` 테이블에 `failed` 로 남습니다. 나중에 파서를 고쳐 다시 처리할 수 있습니다.

## 데이터를 직접 고쳐야 할 때

Supabase 대시보드 **Table Editor** 에서 `ledger_days` 를 열면 날짜별 기록이 표 형태로 보이고 그 자리에서 고칠 수 있습니다. 웹앱의 **입력** 탭에서도 항목별로 직접 수정할 수 있고, **CSV 내보내기** 로 엑셀에 붙여넣을 수 있습니다.
